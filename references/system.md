# 系统：固定共性，展开成独立 Prompt

用户要固定某个角色、产品、元素、视觉语言、镜头运动、变形法则或声音动机时使用。系统可以完全非叙事，也不要求相邻影片连续。

## 系统合同

用简短清单确定：

- **固定项**：明确到可辨识的维度；不要仅写“同样高级”。
- **变量**：每条可以改什么、范围或可选值。
- **组合规则**：哪些变量不能与固定项并存；哪份素材控制哪个固定维度。
- **成功标准**：跨条能识别的共性，以及每条必须独立完成的事件。

用户只给“固定运镜”就只锁运镜，不额外锁人物、色彩、材质。每个固定项都必须在每条 Prompt 中实际展开；无隐式继承、无“同上”、无未替换变量。

固定运动要有**可见终点**，不只给角度数字：相机绕到哪一侧、哪一面从不可见变可见、主体是否允许自转、背景应产生什么视差。不同主体分别翻译同一运动规则，不能机械重复同一句“环绕45度”就认定一致。没有足够空间线索时，精确轨迹应补运镜/白模参考；纯文字系列只能验证方向性相似，不能承诺角度一致。

## 生成与修订

默认给三条有实质差异的示例，用户指定数量时按要求。先定系统规则，再为每条运行任务路由和合同组合；某条可用文生，另一条可用参考，但共享维度不丢。

有冲突的新要求，例如固定蓝瓶却让一条变红：说明冲突，确认它是系统升级还是该条例外。显式用户覆盖可记录为例外，不偷偷污染其余条目。

需要持续迭代时用轻量版本（v1、v2）标注变化范围；不要为一次会话引入数据库或外部配置。未要求保存文件时直接在答复中给规则。

## 系列与连续剧区别

系列共性不等于剧情连续。若用户需要镜头接镜头，另外加入每段输入/输出状态、上一条已接受实拍边界与未来事件排除；还未生成的下一段只能基于计划状态，明确待回读确认。

## 三种系统的检查点

| 固定维度 | 每条必须展开 | 可以变化 |
|---|---|---|
| 产品/角色 | 同一素材绑定、数量、关键几何/外观 | 场景、事件、视角（若未锁定） |
| 视觉风格 | 媒介、颜色关系、光与材质响应、运动节奏 | 主体、场景、故事 |
| 运动规则 | 主体/相机谁动、起点、路径、速度阶段、终点 | 物件、空间、材质 |

交付：当前模式（系统 + 当前生成任务），固定项/变量简表，各条中文 Prompt 与 English Prompt。最终可复制块不含系统变量名或内部合同标签。
